# SCV for Codex 0.20.4-codex.1

이 release는 Codex wrapper를 공식 SCV Core `v0.20.5`에 맞추고, Core
payload와 Deck runtime의 수명주기를 분리합니다.

## 사용자 동작

- 새 project는 host-neutral `scv/SCV.md`를 사용합니다.
- `scv/CLAUDE.md` 또는 `scv/CODEX.md`만 있는 기존 project도 어떤 host에서든
  hydrate 완료 상태로 읽습니다.
- help/status/dry-run은 state file을 만들거나 이름을 바꾸지 않습니다.
- Codex에서는 자연어 요청이 기본이고 `$scv:<action>`은 선택적 exact
  selector입니다. `/scv:*`는 Claude Code의 slash command입니다.

## Core와 Deck runtime

- plugin release에는 검증된 Core `v0.20.5`가 포함되며 정상 실행 중
  network fetch가 없습니다.
- Deck dependency, build output, generated deck JSON은
  `source_payload_sha256`별 외부 cache에 둡니다.
- updater는 이전 vendor와 legacy plugin-root `DeckUI`에서 허용된 runtime만
  열린 FD 기반 snapshot으로 복사합니다. 원본은 수정하거나 삭제하지
  않습니다.
- 다른 host가 만든 cache와 persistent plugin-root runtime이 충돌하면 cache를
  authoritative하게 유지하고 legacy source 전체를 건너뛰어 부분 혼합을
  막습니다. 기존 vendor에서 회수한 runtime의 충돌은 계속 strict하게
  거부합니다.
- runtime migration 뒤 Core 교체가 실패하면 기존 Core는 정확히 복구하고,
  cache에 이미 복사된 entry는 다음 사용에도 유효한 additive 상태로
  남깁니다.
- wrapper는 `0.20.4-codex.1`을 유지하며 Core `0.20.5`와 독립적으로
  versioning됩니다. 자동 Core update도 wrapper version을 바꾸지 않습니다.

## Updater transaction

maintainer updater는 exact manifest tree, provenance, checksum, target
authority를 먼저 검증합니다. 인접 owner lock을 잡은 뒤 parent directory
FD에서 no-replace rename으로 교체하고, commit 직전까지 target, install
stage, parent identity를 다시 검사합니다.

catchable signal과 주입된 실패는 이전 tree를 byte/type/mode-exact하게
복구합니다. rollback을 완성할 수 없거나 process가 강제 종료되면 recovery
data를 보존하고 다음 updater 실행은 fail-closed로 중단합니다.
