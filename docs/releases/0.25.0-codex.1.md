# scv-codex 0.25.0-codex.1

Pins SCV Core 0.25.1 and registers the workspace guard.

## What changes for you

The plugin now **denies** two things instead of merely advising against them:

- Creating `PLAN.md` / `TESTS.md` / `FEATURE_ARCHITECTURE.md` by hand under
  `scv/promote/`. Run `$scv:promote` — it scaffolds those files, consumes the raw
  material, and records where the plan came from.
- Editing code outside `scv/` when no SCV command has run in the session.
  `*.md`, `.gitignore`, `.gitattributes`, `LICENSE` and `.codex/config.toml` are
  exempt.

Editing a plan that already exists is always allowed. Any SCV command clears the
block for the session, including read-only `$scv:status`.

The guard is inert in projects that have not adopted SCV, and it fails open: if
anything goes wrong inside it, your action proceeds and a line goes to stderr.

## Two things to know about hooks on Codex

**Trust is pinned to the hook's contents.** Every release that changes
`guard.sh` returns you to no enforcement until you re-approve through `/hooks`.
This is the one operational cost of the design, and it recurs on every upgrade.

**Hooks are not hot-reloaded.** Restart Codex after updating.

A previous version of `references/journal-hooks.md` said the Codex plugin surface
could not register hooks by itself and that blocking was unavailable. Both claims
were wrong. Verified on codex-cli 0.146.1: `hooks/hooks.json` at the plugin root
loads from the default path with no manifest key, and a `PreToolUse` hook
returning `deny` stops an `apply_patch` before the file is created. The page has
been corrected.

## Also

- Pull requests that change code must now carry the plan they came from. Release
  and Core-sync PRs are exempt; so are docs-only PRs. For a genuine exception,
  put `[no-plan: <reason>]` in the title — an empty bracket is not accepted.

## Honest limits

The guard enforces "an SCV command ran in this session", not "this edit belongs
to planned work". The CI gate checks the second thing, at merge time. A turn
where the model writes no files at all is outside both.

Enforcement here is weaker than on the Claude wrapper: Codex has no skill-
invocation event, so a receipt is minted by observing a shell call to a vendored
Core script — which the model could run itself. It closes the accidental path,
not a determined one.
